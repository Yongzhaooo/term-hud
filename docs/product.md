# term-hud product spec

Last confirmed: not yet confirmed

## Purpose

在 Windows Terminal 标题栏右侧、标签与窗口按钮之间的空白处，常驻显示本机资源状态。用户不必切到任务管理器，就能看到 CPU、GPU、内存、磁盘、网络是否吃紧，CPU 核心最热处的温度，以及 CPU 是否在降频。当前标签是 Claude Code 时，还能看到账户额度和这个会话的上下文用量。

## Expectations

### 位置与跟随

- 默认只在 Windows Terminal 的标题栏里显示：拖动或缩放 WT 时 HUD 先隐藏，窗口停稳 0.5 秒后在 1 秒内贴回原位重新显示，拖动过程中不拖慢 WT；WT 最小化、标题栏被其他窗口盖住、或者没有 WT 窗口时都隐藏，不会浮在其他程序上面。
- 右键勾选“始终显示（置顶）”后，HUD 置顶显示：WT 被盖住或最小化时，仍留在最后的位置。
- 高度贴合标签栏：以标签的实际下沿为准，上下各让 1 像素，背景取标题栏的颜色，不压到终端内容区。
- 有多个 WT 窗口时，显示在面积最大的那个上。几个窗口面积相差不到 5%（比如左右平分屏幕）时，显示在最靠右上角的那个上。(proposed：5% 阈值)
- 不遮挡标签和“新建标签页”按钮：可用宽度为最右侧标签控件到最小化按钮之间的空白。标签增多时 HUD 让位，空白不够时整体隐藏。
- 不影响原有标题栏操作：在 HUD 上左键拖动可以移动 WT，双击可以最大化或还原。HUD 不抢键盘焦点，也不出现在任务栏和 Alt+Tab 里。

### 内容与布局

- 信息密度优先，不留空格子。每个指标是一行 4 格的条目，相邻两条上下叠成一列：CPU 叠 MEM，GPU 叠 DSK；落单的条目改用自己的两行排法（例如 NET 显示为 `↓ 1.2M` / `↑ 0.1M`）。Claude 单独一列。同一列内各字段按位置上下左对齐；标签为暗色，数值为亮色；数值宽度固定，刷新时不跳动。资源数据每 3 秒刷新一次。
- 列标签固定用英文缩写（CPU、MEM、GPU、DSK、NET）。菜单文字按系统界面语言显示中文或英文。
- 各条目内容：
  - CPU：总占用（与任务管理器的 CPU 利用率同源）、核心最高温度、当前频率；落单时第二行是温度和封装功耗。性能被功耗或温度限制时变为橙色，频率前加 `↓`；温度达到 90°C 时同样变橙。
  - MEM：占用百分比、已用、总量。
  - GPU：占用、温度、显存已用、显存总量。只支持 NVIDIA。
  - DSK：活动时间、读速率、写速率。默认统计全部磁盘，可在菜单里指定一块或几块。
  - NET：下行、上行速率、链路速率。默认取流量最大的一块网卡，可在菜单里指定一块或几块。
- 空白放不下时，按优先级从低到高逐条收起，收起后剩余条目重新两两配对：NET、DSK、MEM、Claude、GPU、CPU。一条都放不下时整体隐藏。(proposed：优先级顺序)
- 某个数据源不可用时（例如温度服务没运行），该格显示 `--`，其他条目照常显示。

### Claude Code

- 任一 WT 窗口当前选中的标签是 Claude Code（按 Claude Code 写在标题开头的状态符号判断）时，这个窗口的标题栏显示 Claude 列，内容是该标签的会话。资源条目只显示在目标窗口上，其他窗口只显示 Claude 列。切到其他标签后该列消失。
- 上行：一行高的 Clawd 图标（Claude 橙），后面是 5 小时和 7 天额度的已用百分比。数据是本机默认 `~/.claude` 登录账户的用量，与 `/usage` 一致。优先直接读取 Claude Code 自己缓存在 `~/.claude.json` 里的用量，不发请求；缓存超过 5 分钟才请求一次用量接口（不消耗 token），被限流时逐次加倍等待，最长 30 分钟，期间沿用上次的值。令牌只发给 `api.anthropic.com`，HUD 不保存也不刷新令牌。不需要改动 Claude Code 的任何配置。额度窗口已过重置时间、还没有新数据时显示 `N/A`。
- 下行：当前标签这个会话距自动压缩的进度，与 Claude Code 提示的 “N% until auto-compact” 互补（两者相加为 100%）。按 Claude Code 的算法：压缩阈值 = 窗口（`autoCompactWindow` 与模型窗口取小）− 20000 输出预留 − 13000 缓冲，已用 = 最后一条回复的输入、缓存与输出 token 之和。饼图（与 Clawd 居中对齐）、长条和末尾的百分比显示同一个数，达到 80% 时变橙。会话按标签标题与会话记录里的标题对应，最多延迟 5 秒。(proposed：80% 阈值)
- 5 小时或 7 天用量达到 95% 时，该列变为红色，长条位置改为显示重置时间（5 小时显示 `HH:mm`，7 天显示 `MM-dd`）。(proposed：7 天同样标红)

### 设置

- 右键 HUD 弹出菜单：逐项勾选 CPU、GPU、内存、磁盘、网络、Claude 额度；在子菜单里选择统计哪些磁盘和网卡；“始终显示（置顶）”；“退出”。
- 选择结果保存在 `%APPDATA%\term-hud\settings.json`，重启后保持。

### 运行

- 登录 Windows 后自动启动，不弹出控制台窗口，同时只运行一个实例。
- 界面线程不做跨进程的同步调用：读取 WT 标签（UI Automation）和扫描会话文件都在后台线程完成，WT 卡顿时 HUD 不会无响应。
- HUD 本身以普通用户权限运行。CPU 温度来自以管理员身份运行的 LibreHardwareMonitor 的 Web 服务（端口 8085）。该服务实际监听所有网卡，Tailscale 内的设备可以访问，用户认可这一点，不加防火墙限制。
- 后台占用低，也不拖累 WT：每秒检查一次窗口位置和遮挡，位置、标签和设置都没变时不重新排版；资源数据每 3 秒采一次。WT 的标签只在窗口位置或标题（即选中标签名）变化时经 UI Automation 重查，否则 10 秒兜底一次，拖动中不查，因为每次查询会占住 WT 界面线程十几毫秒。会话文件只复查已知文件的修改时间，每 10 秒重新枚举一次。平均 CPU 占用在总量的 1% 以下（2026-10-14 拖动改动前实测 0.13%，即单核 3%；内存约 260 MB）。

## Non-goals

- 不支持 Windows Terminal 以外的终端，也不做跨平台。
- 不支持 NVIDIA 以外的 GPU，也不支持按标签区分多个 Claude 账户。
- 不做历史曲线、告警、日志。
- 不自带内核驱动，不直接读取硬件寄存器。
- 不嵌入 DeskBox 或其他桌面组件框架。
- 不修改 Windows Terminal 本身，也不依赖它未公开的内部接口。定位只使用窗口坐标和 UI Automation 提供的标签位置。

## Known issues

- 拖动 WT 卡顿（2026-10-14 用户报告，未解决）：开着 HUD 拖动 WT 时延迟明显、占用高。
  - 实测疑点：每次 UI Automation 查询会占住 WT 界面线程约 13 ms（原来每 2 秒一次）；读屏取背景色（GetPixel）约 6 ms；从 HUD 上发起拖动时，原来用同步 SendMessage 把拖动转交给 WT，HUD 的界面线程要一直等到拖动结束。
  - 已试过但撤掉：用 WinEvent 钩子监听 WT 的位置变化来隐藏 HUD，结果拖动时 WT 完全不跟手；改成 PowerShell 每 250 ms 轮询，单核占用从 3% 升到约 9%。
  - 当前版本，待用户实测：UI Automation 只在窗口位置或标题变化时查，拖动中不查；从 HUD 发起拖动改用异步 PostMessage（从 HUD 上拖动是否仍然可用尚未验证）；C# 线程池每 100 ms 只读 DWM 窗口位置，位置一变就用 ShowWindowAsync 隐藏 HUD，PowerShell 每秒的定时器在停稳后重新显示。
- Claude 列消失（2026-10-14 用户报告，在 250 ms 轮询那一版上）：5h/7d、上下文和 Clawd 都不显示，原因未查明。之后两个 WT 窗口都最小化了，当前版本还没确认是否复现。定时器里的异常现在写入 `%LOCALAPPDATA%\term-hud\error.log`，便于排查。
## Open questions

- 模型窗口按型号推断（5 代或带 `[1m]` 的按 1M，其余 200K；已用超过 200K 时按 1M），会话记录里没有窗口大小。设置了 `autoCompactWindow` 时不受影响；没设置且推断错时百分比会偏。Claude Code 的压缩常数改版后也需要跟着改。blocks：未设置 `autoCompactWindow` 的用户能否信任这个百分比。
